# Gateway 文件与平台验收

Gateway 的角色配置、managed JSON 和 SQLite 账本使用普通跨平台文件 API。
访问遵循操作系统现有权限，程序不要求额外的 UID、mode 或 ACL 条件，不修改已有
用户文件和目录的权限。正常文件及目录链接按平台规则解析。新建文件默认使用
`0600`、目录默认使用 `0700`；这些参数不代表 Windows 的实际访问控制规则。

配置保持规范绝对路径、普通文件类型、字节预算、严格 JSON、角色字段和默认路径
检查。首次配置先完整写入排他临时文件并同步，再通过不覆盖已有文件的原子发布
创建目标；并发获胜者的内容会重新校验，损坏的已有文件不会被默认值覆盖。
配置更新保留内容冲突检查及原子替换，并沿用已有文件的普通权限。

Herdr Gateway从普通文件有界加载schema，核对实际字节摘要后保留编译快照。
运行中的契约使用已加载的内存数据；文件更新在显式重载时读取和校验，不按文件
所有者、权限或inode撤销已编译契约，也不在每次目录查询中重复读取完整schema。

SQLite 继续使用事务、同步落盘和单 writer 排他锁。崩溃锁不会自动删除；在途调用
重开后保留为 unknown，不能重新派发。容量统计计入普通文件与文件链接目标，
不递归进入目录链接，避免成环。网络身份、凭据内容及角色能力校验沿用原实现。

数据库文件软链接先解析到目标名字，父目录别名共用同一实际写锁；Windows还统一
实际文件名。数据库硬链接因不能确定唯一sidecar路径而拒绝。这个限制只用于
SQLite单writer互斥，普通配置及状态文件仍可通过硬链接读取，不要求UID或ACL条件。

[Gateway platforms](../.github/workflows/gateway-platforms.yml) 在 Linux、macOS、
Windows 的 x64/arm64 原生 runner 上构建实际单文件候选，并验证配置读写、原子
发布、SQLite 关闭重开、锁与 unknown 不重派。跨平台支持以对应原生任务结果为准，
不能从 Linux 结果或交叉编译推导。

每个平台运行真实单文件 Gateway 两次，检查配置只读命令、数据库持久化、相同恢复
代次及未配对 MCP 401。Linux/macOS 通过进程信号正常退出；Windows 的测试进程
使用强制结束，确认进程退出及崩溃锁保留后，仅由测试清理自己的锁再重开。
另一个用例在六个平台通过真实生产工厂的 Abort 关闭接口验证正常关闭、释放写锁
及再次打开。Windows 的强制结束不作为正常关闭证据。

全部测试只使用自有临时目录、回环动态端口和合成账本，不注册系统服务，不签发
生产身份，不连接用户的原生会话，不调用模型。此页不声明 Connector 原生进程
或开机服务的跨平台支持。
