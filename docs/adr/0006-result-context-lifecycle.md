# ADR 0006：结果上下文的显式释放

状态：提议；随 #218 的实现 PR 评审。

## 决策

保留完成结果的原 Wire 读取上下文、当前双端策略与 provider 校验。结果原文与句柄在固定 result TTL 内可重复读取；读到 EOF 不代表调用方同意删除，也不自动回收仍有效的上下文。读取容量仍独立限制为默认 128 条，满额在派发事务之前拒绝新调用。

采用现有 `runtime_response_discard` 作为显式释放流程，不以旧结果的持久元数据重建已丢失的原许可，也不引入新的结果读取授权模型。需要长期调用的客户端应在读取并保存所需内容后显式 discard。下一次派发会回收已丢弃结果的原上下文；其他调用的结果仍保持可读。

## 授权

生产 caller 注册表可选 `permissions: { discard_response: boolean }`，缺省为 false。此权限独立于方法的 read / dispatch / cancel 策略：删除仍需当前主体归属、原方法当前双端读取策略和专门删除权限，不能删除其他主体的结果。

本机操作员使用 `rovloom token permissions --principal ID --discard-response true|false` 显式授予或撤回；沿用受保护文件、字节代次检查和原子替换，Gateway 每次重新读取，已建立会话也立即生效。此命令不改变 token、到期时间或方法 grants。create --like 精确复制已有主体权限，renew / rotate 保持当前权限；旧注册表不会自动获得删除权限。

## 取舍

本方案给出可持续的“调用 → 读取 → 显式释放”路径，避免 128 条已完成结果占满后无授权入口可清理。需要同时长期保留超过 128 个可读结果的用户仍受当前预算限制；持久结果读取与连接生命周期解耦需要另行设计。不会把 128 改为任意大、不在 EOF 自动删除，也不削弱撤权、TTL 或 provider 撤回。

## 验证

真实注册表热读与 CLI 授予/撤回、严格字段和类型校验、克隆/轮换语义；真实 Store / Router / Wire / loopback 通道在默认 128 预算下超过该累计调用量，显式释放后继续派发，保留结果可读。现有测试继续覆盖跨主体、撤权、固定 TTL 和原许可失效。合成 native 回包仅用于组件验证，不证明真实 native 长时间运行。
