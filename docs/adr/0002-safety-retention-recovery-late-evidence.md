# ADR 0002：分类、有限保留、隔离恢复与晚到证据

状态：采纳。本 ADR 保存四项安全选择的理由；规范语义与默认值只维护在 [DESIGN](../DESIGN.md)，实现差距与故障门禁见 [实施计划](../IMPLEMENTATION-PLAN.md)。

## 安全分类与参数覆盖独立，未知分类默认拒绝

原生 schema 说明结构，不完整表达副作用、高权限、确认或秘密结果处理。仅有方法枚举、通用 object、Owner 身份或设备广告，均不能建立安全分类。选择在所有角色/模式下拒绝未知、不完整、冲突或不可信分类；通用分派和控制输入还按具体 action 评估。

这保留通用接口的表达能力，同时避免把“能透传”变成默认授权。raw-contract 仅在独立显式范围内放宽参数覆盖，不能弥补安全、来源、传输或秘密交付缺口。派发、逐 input、读取及保留采用各自门禁，不能沿用一个成功标记。要求见 [DESIGN §8](../DESIGN.md#8-能力发现契约与派发授权)与 [§9.3](../DESIGN.md#93-开流逐条-input-和读取)。

## 内容、句柄与去重分别到期，预算覆盖全部受管存储

原文可能敏感，不应因调用历史或去重承诺长期保存。句柄失效也不能代表底层内容删除。因此内容、句柄、最小元数据/墓碑与审计分别设置固定期限，覆盖内联及对象全部读取路径；读取许可不自动允许原文保留，禁存分类可只允许即时交付和最小证据。

有限墓碑本身无法保证旧 key 到期后不被当新请求。选择受信 history_epoch：范围停止新 key 准入早于其墓碑可删除时刻，退役/未知范围缺 key 拒绝。代价是超出可证明历史后不能透明重试，必须明确发起新意图；不承诺无限历史或 exactly-once。

容量预约与全库总额防止把内联、WAL、备份或临时文件变成免费空间。资源不足拒绝新增工作，不能提前删承诺期内墓碑/审计；实际持久化失败保留原锚点并关闭副作用入口。应用预留不等于 OS 保证，证据仍可能丢失。唯一数值表及失败语义见 [DESIGN §12.3](../DESIGN.md#123-内容句柄墓碑与全库预算)、[§12.4](../DESIGN.md#124-预留耗尽与持久化失败)，范围规则见 [§11.2](../DESIGN.md#112-有限去重窗口与旧范围拒绝)。

## 旧备份先隔离，旧授权不能因回滚复活

一份完整旧库可能早于设备撤销、配对消费、discard 或调用送达，签名有效也不能证明当前 ACL。选择恢复先隔离、新恢复代次、旧认证/配对/范围失效及独立重新授权；未知历史不推导未执行，旧队列不重放，恢复原文不能只凭重新授权复活。

这优先保住拒绝边界，代价是恢复需本机受信干预与重新配对。没有独立新鲜度来源时不能承诺检测所有整机回滚，也不能重建备份后的完整历史。支持流程与边界唯一维护在 [DESIGN §5.4](../DESIGN.md#54-备份恢复的隔离边界)。

## 可靠晚到回复可以追加原 attempt 的证据

deadline/取消是观察历史，不能否定后来收到的真实回复。选择允许同一仍有效认证上下文和完整原 attempt 下追加证据、细化 unknown，保留原超时/取消历史，不重新派发、不宣称按时完成或远端回滚。

关联、契约、native source、provider 信任或持久化任何一项不成立则不更新；重复幂等，冲突隔离，旧 epoch/恢复代次不靠重连缓存绕过。原文还受当前读取/保留和固定 TTL/discard 限制，最小元数据不授予内容访问。这提高可对账性，同时不扩大执行或保留承诺；精确接纳条件见 [DESIGN §11.1](../DESIGN.md#111-可靠晚到回复只能补充原-attempt-的证据)。
