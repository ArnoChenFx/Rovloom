# #249 聚合存储量测

## 方法与范围

2026-10-24，Linux x64，Bun 1.4.4，同一云工作区，顺序运行基线 main `12242af` 与本 PR。真实文件 SQLite、DELETE journal、FULL synchronous，保留默认配额和 TTL；不包含网络、native 执行、模型或多机吞吐承诺。原始数据：[基线](249-aggregate-baseline.json)、[本次实现](249-aggregate-optimized.json)。这是一次观测，宿主磁盘抖动可能显著影响尾部，不能当作延迟 SLA。

每个档位独立注册/兑换/连接 32 台合成设备，每设备登记 Luvus 和 Herdr，共 64 个 provider。正式 Store 入口生成 created、not_dispatched、outcome_unknown 三种合法行模板，批量回放 0 / 1,000 / 10,000 / 50,000 条历史，避免准备阶段 O(N²) 的写预算成本。历史混合为 18% created、80% not_dispatched、2% outcome_unknown，带完整目标/绑定与正式审计编码（5 万调用对应 9.2 万审计）；这不是通过 native 执行生成的历史，也不证明 provider 的执行能力。

历史增长前用正式备份入口生成两份快照，预算统计仍访问数据目录、journal 和独立快照目录。5 万条历史的基线库约 149.43 MiB，新库约 150.97 MiB，新增索引有实际空间成本。没有用“单 ledger 的 1024 条”裁剪 Gateway 历史。

budget 在真实写事务内独立采样 60 次，不含提交；registration 是额外 60 次正式 Store 登记的完整事务，含预算、触发器、审计与同步提交，轮转设备/provider；expiry 是同一时点连续 30 次正式 Store.expire，包含过期查询、结果清理、预算、提交和失效监听；此阶段不推进时钟，没有待回收内容。单次到期突发另记，避免用常规维护分位数掩盖大批删除。

## 结果

单位 ms，表内为 p50 / p95，箭头表示基线 → 本次实现。

| 调用历史量 | 写预算 | 登记完整事务 | 常规 expire |
|---:|---|---|---|
| 0 | 0.036 / 0.160 → 0.028 / 0.175 | 0.771 / 1.307 → 1.081 / 2.040 | 0.081 / 0.799 → 0.050 / 0.639 |
| 1,000 | 0.322 / 0.692 → 0.024 / 0.090 | 1.091 / 1.703 → 0.671 / 1.346 | 0.777 / 1.171 → 0.109 / 0.885 |
| 10,000 | 8.278 / 11.324 → 0.024 / 0.095 | 9.568 / 15.518 → 0.648 / 1.340 | 24.837 / 27.744 → 0.043 / 0.314 |
| 50,000 | 46.646 / 53.445 → 0.026 / 0.132 | 47.366 / 53.650 → 0.653 / 1.916 | 152.136 / 495.528 → 0.049 / 0.253 |

5 万条历史一次性跨过 metadata TTL 时，清理全部调用、原有 9.2 万条审计及快照（本轮超时新生成的审计仍保留）：基线约 2,626 ms，本次约 3,494 ms。新增索引和计数使大批删除增加写放大，不能宣称所有场景都变快；当前保留原有同事务清理和提交后通知规则，没有改变 TTL、分批延后回收或扩大服务 timeout。实际持续流量的过期通常分散，但这组结果不证明集中到期具有硬实时预算。

## 决定

热路径的内容/结果/预约计数改由 SQLite 触发器与原变化同事务维护，每次预算只读一行；启动和离线检查仍重算。为 active deadline、待清内容和 dedup expiry 添加索引，不重复更新已清理历史，结果按自己的 call_id 核对；完全到期历史先删除，避免先清正文又删除同一行。5 万条历史下预算与常规维护的线性扫描被消除，完整登记事务也从数十毫秒降到约一毫秒；集中删除成本明确保留为取舍，见 [ADR 0007](../adr/0007-transactional-storage-usage.md)。

复现：在仓库根目录用最新 Bun 执行 `bun --no-env-file scripts/storage/aggregate-benchmark.ts /tmp/aggregate.json`。第三参数可限定档位，如 `50000`。基线复测需在 `12242af` 工作树中放入同一脚本，其余代码不变；JSON 输出必须使用新路径，避免覆盖证据。量测不进入每次 CI，功能回归不依赖机器耗时阈值。
